Reference

The commands, the environment, and where the contracts live.

CLI

heimdall init      initialise a deployment (--admin creates the first administrator)
heimdall serve     run the control plane
heimdall doctor    check the machine and the deployment
heimdall login     sign the CLI in (--device for a browser-approved flow)
heimdall app       list | get
heimdall diff      desired versus live, per service
heimdall sync      deploy (--dry-run, --services a,b, --revision SHA)
heimdall enroll    mint an agent enrollment token
heimdall agent     enroll | run, on the target host
heimdall secret    set a local sealed secret (value via stdin or HD_SECRET_VALUE)
heimdall backup    archive the deployment directory (serve stopped)
heimdall restore   restore it
heimdall contract  regenerate the OpenAPI description and capability matrix

Environment

VariableMeaning
HD_DEPLOYMENTdeployment directory (default ~/.heimdall) — the backup unit
HD_ADDRlisten address (default 127.0.0.1:8080)
HD_FYLO_ROOTdocument root — block storage only, never a sync filesystem
HD_PUBLIC_URLthe URL agents connect to, bound into enrollment tokens
HD_SYNC_INTERVALauto-sync tick (default 1m)
HD_METRICS_RETENTIONrollup retention, 24h–336h (default 25h)
HD_TLSserve TLS with the deployment's certificate (default true)
HD_ADMIN_PASSWORD, HD_PASSWORD, HD_TOTPcredentials, from the environment so they stay out of shell history

Diagnostics

Every error carries a stable HD code and actionable text — never parse the prose. Ranges: HD01xx configuration and secrets, HD02xx rendering and reconciliation, HD03xx providers and agents, HD04xx API refusals, HD06xx the web tier.

Contracts in the repository

  • api/openapi.json — generated from the route table; never hand-edited
  • api/capabilities.md — the matrix, generated from the adapters' own answers
  • schemas/ — the validation schemas for compose input, the DeploySpec, and the registry manifest
  • docs/adr/ — ten architecture decision records for every expensive-to-reverse choice
