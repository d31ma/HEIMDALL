Agents

Deploy to hosts the control plane cannot dial — outbound-only, over pinned mTLS.

The shape

heimdall agent runs on a Docker Engine host behind NAT or a firewall and connects outbound to the control plane over mTLS. The control plane never dials the host; the agent long-polls for work.

Enrollment cannot be intercepted

An enrollment token always carries the control plane's certificate fingerprint. The agent pins that fingerprint before sending the token, so its very first connection cannot be machine-in-the-middled — there is no trust-on-first-use window.

# on the control plane
heimdall enroll --target tgt_... --lifetime 1h
# on the host
heimdall agent enroll --token TOKEN
heimdall agent run

An agent is not a principal

It holds no grant and asks for nothing. It receives the work an already authorized sync produced, for the one target its client certificate names — the identity is read from the TLS verified chain, never from a request field. Compromising a host gains that host's own workloads and nothing else.

Offline is normal

A sync for an offline agent parks as a durable intent and drains on reconnect as one fresh sync. Secrets for agent targets resolve on the control plane and travel with the job over mTLS; the agent never holds a resolver or a store credential.

Metrics without chatter

The agent scrapes its own Engine into a local ring buffer and ships completed one-minute rollups on its poll — raw samples never cross the WAN, and shipping is idempotent per instance-minute so a lost acknowledgement cannot double a chart.
