Security model

The boundaries that hold even when something else fails.

SESAME decides, once

HEIMDALL contains no authentication or authorization logic — no password hashing, no session table, no role check in any handler, enforced by a CI gate. A dedicated security engine answers every question, exactly once per mutating route, at the boundary. Handlers receive already-authorized requests. An errored, timed-out, or unrecognised decision is a deny.

A closed verb vocabulary

Routes name actions from a closed set — app:sync, registry:bind, observe:logs, and so on — and ship in four role bundles (viewer, operator, admin, owner). Log access is deliberately separate from app access: container logs routinely contain what an operator who may deploy still should not read.

An audit log that cannot be rewritten

Every decision is recorded with the policy version that made it, so "why was this allowed in March" is answerable without replaying policy. The audit collection is authoritative, not a projection — a log you can regenerate is a log you can rewrite.

The web tier holds no authority

The browser talks to a thin proxy that attaches a session from an httpOnly cookie and forwards. No token in page-readable storage, no business logic, no authorization opinion — one door, with an allowlist that keeps it from becoming a request forge.

Everything else

  • Secrets are references; no value is ever persisted or logged.
  • Agents enroll against a pinned certificate fingerprint and are not principals.
  • Webhooks verify an HMAC and never parse the payload.
  • Repositories can require signed commits before anything is rendered.
  • The registry manifest cannot declare principals, grants, secret values, or agent enrollment.
