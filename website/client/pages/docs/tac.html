Get started

A control plane on your own machine, deploying a compose repository, in five steps.

1 · Install the dependencies

HEIMDALL supervises three child binaries — FYLO for storage, SESAME for security, CHEX for validation — and drives the real git. The install script fetches the pinned versions; sops and age are optional, for in-repo encrypted secrets.

scripts/install-deps.sh

2 · Initialise a deployment

One directory holds everything — the document root, the security engine's state, and every key. That directory is the backup unit.

HD_ADMIN_PASSWORD=•••• heimdall init --admin ops
heimdall serve

3 · Declare your registry in git

Open Registry in the web UI and bind one root repository — the single interactive act. Its registry.yaml declares the rest: projects, repositories, targets, and applications. Every later change is a commit, with review and rollback for free. See The registry in git.

# registry.yaml, in the root repository
projects:
  - name: shop
repositories:
  - project: shop
    name: site
    url: ssh://git@forge/shop/site.git
applications:
  - project: shop
    name: site
    repository: site
    target: local
    path: deploy
    sync_policy:
      automated: true
      self_heal: true

4 · Reference secrets, never values

In your compose file, a secret is a reference resolved at apply time — from a SOPS-encrypted file beside it, a cloud secret manager, or the local sealed store. No value ever enters a stored document. See Secrets.

services:
  api:
    image: ghcr.io/example/api:2.1
    environment:
      DATABASE_URL: "${secret:sops/secrets.enc.yaml#database_url}"

5 · Watch it converge

The web UI shows the resource tree, per-instance dashboards with deploy markers, tailing logs, and one Activity table answering "what happened around 14:07". Sync on a webhook nudge or the loop's own tick; drift heals itself if the application consented. See Sync, drift and rollback and Observability.
