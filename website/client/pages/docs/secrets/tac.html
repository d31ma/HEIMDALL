Secrets

References everywhere, values nowhere — resolved at apply time, inside one call.

The rule

A secret in HEIMDALL is a reference. Values resolve at apply time only, exist for the duration of one provider call, and never enter a stored document, a plan, a diff, or a log. There is deliberately no route that returns a secret value, and no verb that would permit one.

Referencing a secret

An environment variable's value must be a whole reference — interpolating one into a larger string is rejected at render, because the assembled value would have to be stored:

services:
  api:
    environment:
      DATABASE_URL: "${secret:sops/secrets.enc.yaml#database_url}"
      API_KEY: "${secret:local/api-key}"

Stores

SchemeBacked by
local/<name>The deployment's sealed store — AES-256-GCM files, keyed inside the backup unit. heimdall secret set writes it; values arrive via stdin or environment, never argv.
aws-sm/<region>/<name>AWS Secrets Manager
azure-kv/<vault>/<name>Azure Key Vault

SOPS: secrets beside the compose file

Encrypt with SOPS (age, PGP, or a cloud KMS), commit the ciphertext, reference it. The ciphertext is read from the applying revision's own commit — rotation is a commit, rollback decrypts the old ciphertext — and decryption drives the real sops binary with the plaintext crossing only an in-process pipe. If <deployment>/keys/age.key exists it is offered to SOPS automatically, keeping the key inside the backup unit.

File secrets on Swarm

Compose file secrets deploy to Swarm with the one value source GitOps can honour — a reference. Each distinct value becomes a content-hash-named Swarm secret, services reference the name their value hashes to, and rotation is an ordinary service update: no rename dance against Swarm's immutable secrets. Stale versions are pruned once nothing references them.

services:
  api:
    secrets: [db_password]
secrets:
  db_password:
    x-heimdall-ref: sops/secrets.enc.yaml#db_password

Registry credentials

Image-pull credentials follow the same rule: a registry document holds a password_ref, and the value exists only inside the one pull that needs it.
