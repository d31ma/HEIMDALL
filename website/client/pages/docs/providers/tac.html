Providers and capabilities

Five runtimes answer one model — and refuse, by name, what they cannot express.

The adapters

Docker Engine, Docker Swarm, Amazon ECS, Google Cloud Run, and Azure Container Apps. Adapters are the only code that knows a cloud exists, they call the cloud SDKs directly (never Docker's deprecated compose integrations), and every adapter passes the same conformance suite.

The honest matrix

Each adapter's Capabilities() answers what it can and cannot express, the published matrix is generated from those answers so it cannot go stale, and a plan that asks for something rejected fails with the offending service and the alternative named (HD0300). Highlights:

Never silently drop

The compose parser models a deliberate subset and decodes with unknown-field rejection: a directive HEIMDALL does not model fails by name and line at render time. What a modelled directive means per provider is the capability matrix's job at plan time. Between the two, nothing you wrote can quietly not happen.
