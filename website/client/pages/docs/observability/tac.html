Observability

The screens an operator lives in during an incident — without building another metrics database.

The application view

An ArgoCD-style resource tree — application, services in dependency order, running instances — with health on every node, a table twin, a search that filters both, and one Activity table merging HEIMDALL's operations with the runtime's own events, because "what happened around 14:07" is one question.

Instance dashboards

Instances on Docker Engine, Swarm, and ECS get a Grafana-style page: stat tiles (health, state, restarts, started, revision, image), chart panels — CPU, memory, memory-of-limit, network, block I/O, PIDs, CPU throttling, network errors — with deploy markers drawn where revisions landed, and the tailing log underneath.

Cloud Run and Azure Container Apps are the deliberate exception: they refuse metrics and logs and name their platform's own store instead (Cloud Monitoring, Azure Monitor). An instance on those runtimes still shows its identity, health, and the commit that put it there — HEIMDALL simply does not proxy a telemetry stack that already exists.

Choosing what to collect

A service declares which metric groups its dashboards carry, in the compose file. Unchosen panels are absent, not empty; a typo is rejected at render with the vocabulary named:

services:
  web:
    labels:
      heimdall.metrics: "cpu, memory, network"
# vocabulary: cpu, memory, network, block, pids, throttling, net_errors

Retention

Docker Engine metrics flow scrape → in-memory ring (one hour) → one small rollup document per instance-minute, kept 25 hours by default. HD_METRICS_RETENTION extends that up to 336h; a bad value fails startup loudly, because the alternative is a week of history silently pruned to a day. Past two weeks, the honest tool is a real time-series database — which HEIMDALL deliberately is not: provider-native metrics stores answer for the clouds.

Logs

Logs stream from the runtime and are never stored — a log store is another product, and an unstored log is one a secret cannot leak into. Retention is your logging driver's or your cloud's setting. There is deliberately no interactive container shell: streaming logs only.
